# Auditoría de Código — ARHIAX RE (Web de Dictámenes Inmobiliarios, Barranquilla)

**Alcance:** `api/index.py` (FastAPI/Vercel), `public/index.html`, módulos `api/*.py`, `database.db`, `vercel.json`, `requirements.txt`, `tests/test_arhiax_re.py`. Método: lectura estática (read/grep/glob, sin ejecución).

---

## RESUMEN EJECUTIVO

1. **La aplicación, tal como está en el repositorio, no puede arrancar:** `api/index.py:178-179` contiene un `if` sin cuerpo (la línea 179 `return` está al mismo nivel de indentación) → `IndentationError` en tiempo de importación. Todo el API devuelve 500 y, aunque Vercel sirva `public/index.html` como estático vía `vercel.json`, el login y todos los endpoints fallan. Es el hallazgo más grave y debe verificarse/corregirse primero.

2. **El "login" es seguridad por oscuridad pura, no autenticación:** la contraseña (`[REDACTED]`) está hardcodeada en `index.py:62`, el token devuelto es una cadena estática (`index.py:138`) y **ningún** endpoint del backend valida el token (el `Depends` importado en `index.py:10` nunca se usa). El frontend solo oculta el portal si `localStorage.arhiax_token` es truthy (`index.html:571,580-584`). Cualquier persona puede invocar `/api/dictamenes/generar`, `/api/resolver-matricula`, etc. sin credencial alguna.

3. **El flujo dictamen está roto en varios puntos y el PDF final es en gran medida una plantilla estática del caso demo "Napoli":**
   - El endpoint stateless `/api/dictamenes/generar` nunca pasa el `certificado_path` a `compile_pdf` (`index.py:547-559`), por lo que `analizar_certificado(None)` (`pdf_compiler.py:113-115`) produce siempre el hallazgo **H-01 AUSENCIA DE CTL (ALTO)** y semáforo ROJO, **aun cuando el usuario subió el certificado**.
   - Los motores dinámicos (score, SARLAFT, ruta, POT, hidrológico) están importados pero **nunca invocados** (`pdf_compiler.py:35-37`): el PDF muestra scores fijos (88/100, 84/100…), tabla POT fija, texto fijo "Conjunto Napoli … Torre 8" y "0 polígonos de amenaza" sin importar los datos reales.
   - Datos personales reales del caso Napoli (nombres, cédulas, acreedores, NUPRE) hardcodeados en `dictamen_data.py:217-234` se imprimen para **cualquier** predio de Miramar.

4. **Persistencia en Vercel inexistente por diseño:** SQLite (`database.py:8`) y assets (`index.py:66`) viven en `/tmp`, efímero y por instancia. Los casos, uploads y PDFs generados desaparecen entre invocaciones y divergen entre instancias concurrentes. El frontend lo "resuelve" guardando los casos en `localStorage` (`index.html:573-574`), pero los IDs son `Date.now()` sin crear el caso en el servidor, lo que deja a `/update` y `/delete` en 404.

5. **Hay buen diseño aislado** (SARLAFT honesto con hashes, ruta de verificación por catálogo, amortización francesa con disclaimers), pero está desconectado del flujo real. Los tests (11) no cubren `pdf_compiler.py`, `index.py` ni los endpoints, y 3 de ellos dependen de red (Nominatim en vivo).

## FLUJO ROTO / RIESGOS DE PRODUCCIÓN

### Flujo real (frontend → PDF) y dónde se rompe

1. **Login** (`index.html:590-606`): POST `/api/login` → con H-01 presente, responde 500 (error alert). Aun corregido H-01: token estático sin verificación server-side (H-02/H-03).
2. **Crear caso** (`index.html:661-713`): guarda en `localStorage` con `id=Date.now()`; **no crea el caso en el backend** (H-09). `barrio` inferido por `includes("recreo")` (línea 672).
3. **Subir certificado** (`index.html:777-824` → `index.py:256-366`): el servidor escribe `ASSETS_DIR/case_<id>/certificado.pdf` (en `/tmp`) y hace `UPDATE … WHERE id = <Date.now()>` que afecta 0 filas (el caso nunca existió). Devuelve `extraidos` OK → la UI muestra el área. Las imágenes (sombra 9am/3pm, mapa) **solo quedan en memoria del navegador**; al recargar la página se pierden aunque la UI diga "Cargado".
4. **Editar / Eliminar** (`index.html:839-914`): `/api/dictamenes/{id}/update` y `DELETE` → **404 "Caso no encontrado"** siempre (H-09).
5. **Generar PDF** (`index.html:922-968` → `index.py:486-579`): stateless; recibe los archivos en memoria. `compile_pdf` corre con `certificado_path=None` → **H-01 AUSENCIA DE CTL (ALTO) + semáforo ROJO en el PDF descargado**, sin anotaciones, sin carga económica, con score/POT/textos fijos del caso Napoli (H-05, H-06, H-08). El PDF además hace 2 llamadas a Overpass y genera 2 mapas (M-02) en el camino síncrono → riesgo de timeout.
6. **Estado COMPLETADO** (`index.py:333-360`): solo alcanzable en el flujo stateful (que el frontend no usa) y el `pdf_path` apunta a `/tmp` → desaparece en el siguiente cold start (H-10).

### Riesgos de producción (Vercel)

- **Función no arranca** (H-01) → todo `/api/*` en 500; el HTML estático se sirve por el rewrite de `vercel.json`.
- **Timeouts**: 3 intentos Nominatim × 8 s + Overpass 1.5 s × 2 + Pillow + ReportLab superan fácilmente el límite de función (10–60 s según plan) → 504 y reintentos.
- **Estado efímero e inconsistente**: `/tmp` por instancia → pérdida de datos entre invocaciones y divergencia entre instancias concurrentes (H-10); SQLite "database is locked" bajo concurrencia (M-10).
- **Falsos negativos geoespaciales**: GeoJSON ausente/fallo del motor → "Sin afectación" (H-11); centroide de Barranquilla si Nominatim falla (H-12); ambos llegan al PDF como veredicto "verde".
- **Documento legal con datos falsos/fabricados**: scores fijos, texto "Conjunto Napoli/Torre 8", POIs inventados, imágenes de otro predio, PII de terceros (H-04…H-07, M-03).
- **Sin autenticación**: cualquiera puede disparar `/generar` (cómputo+red de terceros a cargo del servicio).
- **Encoding**: el código fuente es UTF-8 limpio; el riesgo real es la extracción regex de CTL reales con texto mojibake (B-08) → área/dirección faltantes con fallback silencioso.
